# 换模型与迁移操作单

## 1　模型可以换，4S 仍按原接口传图

每个候选有一个本机名称、一条接口地址、一个模型 ID 和该端点专用的密钥。已验证并保存 DeepSeek 官方直连，正式外发目前暂停，端点为 `https://api.deepseek.com`，型号为 `deepseek-flash`。百炼的业务空间地址和百炼密钥需由公司另行提供。同一供应商下的不同型号也可以起不同名字，例如 `bailian-plus` 和 `bailian-flash`。

1. 运行 `./4s configure-model bailian` 保存候选。按提示输入完整 Base URL、准确的视觉型号和该端点的密钥。自定义名称例如 `./4s configure-model mimo-pilot`。请从供应商取得具有图片能力的实际型号。
2. 运行 `./4s model-check bailian` 可单独试通。它发送生成的随机数字图，再用合成测试图走 PPE 请求和严格 JSON 校验。每次完整检查调用模型两次，供应商可能计费。
3. 先用获准外发的人工标注样本比较误过滤数、正确筛出的误报和不确定比例，记录样本构成及 PM 的接受标准。合成图探测只验证连通与格式。确认供应商数据许可（含待审积压）并决定切换时运行 `./4s model-use bailian`。该命令自行做相同验证，成功后保存选择，所以可以直接执行这一步。失败会保留原来的活动配置。然后执行 `./4s restart` 让运行中的进程加载新选择。
4. 打开后台「正式收件」确认显示新型号。用获准提供的样本验收；查看详情里的实际模型、理由和耗时。原已完成任务保留原结果。尚未审核及需要再次推理的任务会使用重启后选定的模型。已保存结果的回调重试直接重发该结果。
5. 要回切本次已验证的配置，运行 `./4s model-use deepseek` 再 `./4s restart`。若云接口不可用，运行 `./4s model-use off` 再重启，正式 PPE 先收图排队。候选配置仍保存在数据盘。另可用 `./4s model-list` 查看保存的名称和重启时加载的选择。

三项调用能力是 OpenAI 兼容的 Chat Completions、内联单张图片及 JSON 对象输出。输出须能提供两个布尔证据字段和中文理由。厂商若使用独有协议，需要适配 `app/review.py` 的传输部分，再跑验证。端点与 Key 按组选择，模拟队列始终留在本机。本机不会自动转往其他厂商。新规则的审核尝试在各自数据库 review_history 表记录配置名、端点源站、请求和返回的型号、开始/结束时间、状态与规则版本。

`examples/model-profile.example.json` 是结构示意。应用生成各环境的收件令牌和本机回调令牌。请用命令维护实际配置。活动快照及候选密钥存在数据卷的 `var/config.json`，仅本机账户可读。审核包内的资料可供其他 Agent 使用。[DeepSeek 图片接口](https://api-docs.deepseek.com/zh-cn/guides/vision/) · [百炼视觉接口](https://help.aliyun.com/zh/model-studio/vision/)

## 2　迁移前准备

Mac 试点默认卷为 `/Volumes/Data`。目标地址、供应商权限、磁盘容量和运维方式需要 IT 确认。已将挂载点参数化，macOS 会校验外置卷，Linux 实现按独立挂载点校验并拒绝系统根卷。项目目录和状态目录都须位于该卷内。使用支持 SQLite 文件锁和 WAL 的本地磁盘。目标 Linux 主机尚未实际验收。

目标机以专用账户运行。挂载卷后设置 `FOUR_S_VOLUME` 并把源代码解压在卷内，例如 Linux 的 `/srv/4s-data/review`。将此环境变量也提供给将来的服务管理进程。默认状态目录是项目内的 `var`。如另设 `FOUR_S_STATE`，它必须是本项目目录下位于同一卷的子目录。

在目标机重建 .venv。先创建 `var/tmp`，将 TMPDIR 和 pip 缓存指到数据卷，按 README 安装依赖。不同系统的虚拟环境不宜复制。为新入口安排公司网络路由、VPN 或 HTTPS，入站端口当前为 TCP 8765。管理页面只接受回环访问。同一主机转发流量时应只把平台接口和文档发布给 4S。迁移后 4S 要更新服务地址或由 IT 切换公司的固定域名；若 4S 回调或模型出站限制使用 IP 白名单，也需更新新主机出口地址。

## 3　正式搬迁的顺序

| 步骤 | 动作 | 核对证据 |
|---|---|---|
| 1. 预演 | 在目标的隔离目录用合成图验证安装、上传、模拟回调、重启和模型连通 | HTTP 202、同编号再传 200，记录可查。评测使用独立配置及临时测试地址 |
| 2. 约切换窗口 | 4S 暂停向旧地址推送，将期间报警和原图留在平台队列。记录两边最后一个确认任务及时间。停止旧 Mac 服务 | `./4s stop`，进程已退出，后续只保留一个运行主机 |
| 3. 冷复制 | 按公司授权渠道传整个 `var/live/` 与 `var/mock/`（含存在的 WAL 文件），另行安全迁移或重新配置 `var/config.json`。保留冷备份 | 校验文件 SHA-256、每库任务数/图片数；核对接口令牌、两端回调约定、目标账户及文件权限 |
| 4. 启动目标 | 使用新主机的虚拟环境，执行 `./4s start`；检查健康接口、后台和原样本 | SQLite `PRAGMA integrity_check` 返回 ok，`PRAGMA foreign_key_check` 无结果；原任务号、图片、时间及结论一致 |
| 5. 确认投递 | 只保留新实例运行。待处理任务和未确认回调可立即恢复；让 4S 验证相同 task_id 的重复回调只通知一次 | 未完成任务能继续，已完成任务保持历史结论。确认回调端实际落库而非仅返回 HTTP |
| 6. 切流 | 4S 更新地址，从平台自己的服务器试传一条，然后用原编号重传窗口内积压 | 新收件持久化，4S 查询、回调与后台对应。核对收件数、失败数、积压最老时间和磁盘余量 |

配置内含敏感凭据，实际客户数据库与源码审核包独立交接。`service.pid`、锁文件、虚拟环境、缓存和临时文件由目标主机重新创建。服务启动可能立刻处理积压，要先准备好接收方再启动带真实数据的实例。

## 4　回退

**新机尚未接单、送审或回调**时，可以停止新机，将入口切回旧机，以旧机原库恢复。**新机已经发生写入或投递**时，先让平台暂停推送，停止新机，把新机最新的两库和一致的配置冷备回旧机，核对完整性和窗口任务，再启动旧机并切回。回调可能已到 4S 但确认尚未写入，双方仍按任务号去重。不要让两个各自持有库副本的实例同时消费同一批任务。

目前完成的是同一台 Mac、同一外置卷内的隔离恢复演练。新主机的实际网络、文件系统、备份恢复时长、自动启动和运行指标应由迁移验收记录确认之后再切流。
