# 公网联调与审阅处理

本机当前已启用 DeepSeek deepseek-flash。正式入口把原图保存到 Data 盘并自动送审真实 PPE 任务，返回结论供 4S 自行决定处理。4S 尚未提供正式回调。启用时无待处理真实任务，隔离实例使用合成图实际验证了收件、模型识别、保存和查询。现场图准确率待评测。

## 模型设置页面

本机管理后台可保存多组供应商地址、模型 ID 和密钥。页面显示已保存状态，API Key 不回传浏览器。启用前沿用合成图探测，验证成功后立即切换；失败时保留原模型。进行中的任务继续使用领取时的模型和凭据，暂停期间的待处理任务在下次启用时继续处理。管理接口仅限本机并使用后台认证。

## 当前对接协议

以《4S 报警图片复核 API v1》为准。所有项目使用同一套异步复核流程。此前固定返回结果的演示记录保留在数据盘，并从业务列表和统计中排除；实际模型审核过的记录继续显示。人员框可选，只作原算法元数据，复核范围由 ROI 决定。平台按项目控制送审、展示和通知。会议提出的 30–60 秒为试点期评测目标，现场吞吐及端到端耗时仍待实测。会议中讨论的故障通知收件人、平台等待上限及积压窗口待双方确定。

## 给 4S 的交付

1. 用 `./4s public-status` 查看账号绑定的固定公网根地址。交付 `/docs` 和 `/integration.zip`，通过公司安全渠道把 `./4s token live` 的输出单独交给 4S 对接负责人。
2. 4S 使用真实项目编号、报警编号和 `POST /api/v1/tasks` 提交报警，按任务号查询；原样重传返回同一任务号。公网只有一套 API。
3. ngrok 将 HTTPS 请求转发到本机受限网关。试点账号凭据和域名绑定记录在 Data 盘。重新登录并挂载 Data 盘后运行 `./4s start`，恢复同一网址；`./4s stop` 停止整套服务。
4. 真实工地图的传输和送往模型分别确认。4S 按项目策略展示和通知；正式回调需 4S 提供 HTTPS 地址及独立令牌。

## 历史版本审阅意见处理

| 项目 | 已采取的措施或待决事项 |
|---|---|
| 1　无人、非现场、证据不足 | 新规则 ppe-2 要求 is_site_image 和 relevant_person_visible。二者有一个为 false 即无法确定。不能解码的输入在收件时拒绝；能读但模糊或遮挡的图要求模型保留疑问。是否有可见人员仍依赖模型判断，需要带标签现场图评测。 |
| 2　观察期开关 | filter_enabled 默认关闭。只有已启用模型和过滤的正式新收件才有过滤资格，并须审核完成且明确误报。启用后不追溯观察期记录，关闭并重启会收紧已有建议。此前已由平台执行的隐藏需平台处理。切换模型会将过滤开关置回关闭。 |
| 3　外发许可 | 活动配置已切到 off。双方确认真实工地图可发往指定端点后，再选择模型并重启。启用会处理库存的 PPE 任务，需一并确认。 |
| 4　无结果时怎么展示 | 给 PM 的试点建议是“4S 照常展示和通知，复核只追加标记”。收件失败仍用原编号重试。平台实际逻辑、超时及迟到通知由 PM 和 4S 签认。 |
| 5　回调协议 | 公网继续要求 HTTPS 与单独令牌；本机回环允许 HTTP。4S 未提供回调时先按任务号查询。若要使用企业私网地址，先确认公司 VPN 路由、传输方式和鉴权。 |
| 6　模型准入、审计 | 真实合成数字读回和测试卡必须通过，测试卡需返回 uncertain。将现场人工标注评测列在模型切换操作单。新审核尝试的 profile、endpoint_origin、requested_model、actual_model、rule_version、起止时间、状态写入各库 review_history，与领取/完成分别同事务。该版本记录源站；规则升级需同步升级版本和回归样本。 |
| 7　回调积压 | 管理页显示已耗尽重试的数量，后台可逐条重发，运维可执行 `./4s callbacks-retry live` 按环境批量重发失败回调，复用已有结论。4S 可按任务号查询。夜间值班的主动通知渠道待运维指定。 |
| 8　后台与公网隔离 | 公网网关仅开放收件、按号查询、健康、对接文档。管理服务另要求回环来源、本机 Host、独立后台密码，并拒绝代理标识。后台账号 admin，密码由 `./4s token admin` 在本机获取。 |
| 9　容量与迁移 | 缺少峰值吞吐、模型限额、持续时延、磁盘增长和恢复时长测量。历史 4,845 ms 是两次探测耗时，不能当成单条业务延迟。扩量前用获准的样本实测并决定并发与保留期限。迁移仍为单写主机冷迁移；两份独立复制的 SQLite 库之间无法用各自的本地租约排他，多主需要共享协调机制。 |
| 10　幂等 | 继续比较原图字节和规范化后的业务字段。文档要求平台保存原件和完整字段重传；同号改图或改 ROI 返回 409。 |
| 11　默认型号、运行环境和传输 | 新配置的默认型号为 deepseek-flash。现有环境可通过 model-use off 暂停。外部调用使用 HTTPS。Python 3.9 运行时升级列入目标机验收；外部审阅者报告 Linux/Python 3.12 上三组离线测试通过，不能替代正式目标机验证。 |

## 历史运行证据（双环境版本）

- 公网域名的真实 HTTPS 模拟提交返回 202，按任务号查询为 completed/delivered，同号原样重传返回 200 及相同任务号，任务号为 `<TASK_ID>`。测试用生成的图片和模拟令牌；正式库未混入此次样本。
- 香港外部 HTTP 探测节点从公网对 /healthz 得到 200，响应显示模型和过滤均关闭。4S 仍应从实际发送服务器自行验通。公网管理页和内部模拟回调入口均返回 404，匿名推图返回 401。
- 新规则在本机离线复验了无人图、非现场图、默认关闭、开启后只对新任务生效、云审核异常、回调重试、冷迁移和后台鉴权。用已保存的 DeepSeek 候选真实探测，随机数字读回正确，整张非现场测试卡返回 uncertain，两次调用合计 3,880 ms。
- 业务验收还缺由 PM 确认的现场标签。要估计真实违规被误过滤的比例，须单列人工确认的真实违规数与误过滤数；报告样本覆盖、相关性和置信界限。只有设备联通或一次合成图通过，不能据此宣称 PPE 准确率。

## 历史交付复验（API 1.2.0）

- API 版本 1.2.0。按对接方修订稿合并了观察期提示、首页快速开始、4S 实现要求、正式及模拟响应示例、重试与耗时。正式安全帽和反光衣在模型关闭时等待，危险区域和组合报警保留原有范围规则。提交与查询均包含任务附加字段。耗时例中的 2,826 ms 是历史单张合成图记录，3,880 ms 是两次探测合计。60 秒和 10 秒分别为模型与回调请求的网络超时。
- 网页、Markdown、OpenAPI、联调包均通过同一份代码和文档生成。已在公网用下载包的脚本和合成图验证，首次 202、重传 200，同一任务号 `<TASK_ID>`，模拟回调已确认。匿名健康接口仅返回 `{"status":"ok"}`。正式实例的本机鉴权后台确认模型、过滤建议及正式回调均关闭。
- 在 Data 盘隔离目录通过 `pilot.py`、`profile_switch.py`、`relocation.py`、`fixed_entry.py`。最后一项在回环接口使用专用测试证书，验证 IP 与证书核对、匿名健康、后台隔离、正式 PPE 等待、整套服务停止后使用原 URL 重传仍返回同一任务号。生产公网证书和真实公网重启验收仍待网络接入。
- Mac 有线接口当时为 DHCP 分配的 `<REDACTED_IP>`。指定有线网口两次观察到公网出口 `<REDACTED_IP>`，系统默认路径另经过虚拟网络接口。公司网关 `<REDACTED_IP>` 的管理入口要求登录，WAN 分配记录和静态性尚未确认。对候选公网地址 443 的 HTTPS 检查超时。没有变更路由器、映射、防火墙或 DNS。
- 固定接入采用公司固定 IPv4 的 HTTPS 证书和端口映射。负责人用 README 的“使用固定公网 IPv4”完成证书部署及外网测试。临时隧道仍供模拟联调；4S 手册统一使用 `<BASE_URL>`，联调包不嵌入短期域名。固定入口的证书、密钥和业务数据均不随审核包分发。
