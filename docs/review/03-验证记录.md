## 2　离线回归与搬迁演练

在数据卷内解压源码后，按 README 安装依赖并创建 var 目录。在项目根目录运行：

```sh
.venv/bin/python -B tests/pilot.py
.venv/bin/python -B tests/profile_switch.py
.venv/bin/python -B tests/relocation.py
```

| 脚本或检查 | 测试方式 | 结果 |
|---|---|---|
| pilot.py · 收件 | 并发重复提交；改内容重用编号；坏图、坏 ROI、错误令牌和跨环境查询 | 同一任务只有一次 202，重复 200，冲突 409，错误输入被拒；原图可读 |
| pilot.py · 审核与投递 | 本机 HTTP 模型和平台替身；主动制造 503、坏 JSON、回调拒收、人工重发 | 模型最多尝试 3 次，回调最多尝试 5 次；耗尽后的技术失败没有业务结论，should_filter=false；重发复用已存结果 |
| pilot.py · 中断 | 在进行中的审核和回调分别强制终止隔离进程，重启 | 审核被重新领取；回调复投相同结果；收到两次的情况可按 task_id 去重 |
| profile_switch.py | 使用两个不同的测试端点/密钥；模型探测使用受控替身；切换 A→B→A、注入候选失败、切至 off | 端点、型号、密钥成组回切，探测失败不替换活动快照；off 保留候选并禁止从百炼环境变量恢复推理 |
| relocation.py | 两个隔离源码目录和端口；先停旧实例，复制两库及测试配置，校验摘要后在新目录启动 | 两库完整性及外键检查通过，图片字节一致，旧任务号、时间、结论、回调收据、待模型队列和幂等重传保留 |
| 试点主机再检查 | 查询健康接口、读取后台活动型号、检查依赖 | 服务正常响应、活动型号正确、pip check 通过 |

离线重试测例只在测试库中快进下一次尝试的等待时间。恢复演练使用同一台 Mac 的两个目录和同一 Python 运行环境。没有在另一台物理机、Linux 上或真实 4S 接收器上执行该演练。归档的验证范围为单机试点。

## 3　交接清单

- **4S 开发**：从平台服务器测试到 Mac 的网络、获取正确环境令牌、提交获准的样本、提供正式回调 URL 和令牌、确认重复回调只通知一次。
- **PM 与现场同事**：提供安全帽/反光衣样本和人工结论，确定可接受的误过滤风险、区域/组合规则及超时展示策略。
- **模型账号负责人**：本次提供的是 DeepSeek 直连权限。公司百炼、MiMo 或其他候选若要参与比较，需提供各自可用视觉型号、端点、额度与数据使用许可。
- **IT 与服务负责人**：确定迁移目标和专用卷、稳定访问地址、备份策略、保留期限、监测方式和峰值容量。正式回调、目标机迁移与现场质量验收各自单独签认。
