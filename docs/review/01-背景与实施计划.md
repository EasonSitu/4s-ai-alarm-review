# 背景、决策与实施计划

## 1　事情是怎样开始的

现场 AI Cam 用小算法识别未戴安全帽、未穿反光衣等情况。触发时现场已报警，同时把抓拍图和报警前后约 15 秒的视频传回原平台。客户看到部分误报，产品希望在平台交付给客户之前多做一次复核。PM、4S 开发和审核服务负责人讨论了提交、展示、通知、服务中断及回写问题。

一期只看已经触发报警的单张图片。平台负责挑出启用试点的项目和事件；审核服务没有摄像头列表、持续取流或视频处理任务。云模型可更换。在这台 Mac 上先证明“收得到、存得住、查得到、回得去”，再用人工核对的现场样本决定能否过滤，以及是否值得扩大使用。

初始项目目录为空。需求依据包括负责人本次明确说明和引用会话《误报检测方案梳理》内可读的会议内容、方案和边界。会话提及的独立提示词附件未随请求交付。AIBox 参考站打开到验证码登录页，内部列表与详情未核对。产品行为以以下已确定规则和对接协议为准。

## 2　已经约定的业务判法

| 原报警及图片情况 | 送回 4S 的意思 |
|---|---|
| 报未戴安全帽，约定区域内任何人头部清晰、明确没戴帽；其他人被遮住 | 有效。看到一个明确违规者已经足够 |
| 原算法框里的人戴着帽，区域内另一人明确没戴 | 有效。人员框和约定的审核区域是两个概念 |
| 报安全帽，图里只看出有人没穿反光衣 | 继续判断安全帽。反光衣不能当作这条报警的证据 |
| 能充分观察与本条告警有关的人和区域，足以排除本条违规 | 误报，观察期始终保留；经签认开启过滤的新正式任务才可建议过滤 |
| 没看到明确违规，也看不清相关人员的头部或躯干 | 无法确定，保留 |
| 接口超时、模型返回坏 JSON、推理失败 | 技术失败，结论为空，保留 |
| 危险区域、组合报警 | 一期返回无法确定并保留。危险区域需定义多边形、坐标基准及进入条件；组合报警需定义任一项或全部项成立 |

已有矩形 ROI 时按原图显示方向归一化，在模型调用前转正并裁图。平台省略 ROI 即审核整图。原报警时间一直跟随任务，上传时间、审核完成时间分别记录。是否展示、是否推送通知、补处理是否追发通知由平台执行。

## 3　从原设想到当前实现

| 讨论中的问题 | 目前的选择及影响 |
|---|---|
| 收到图片后要不要等模型答完？ | 异步。4S 提交成功即可拿到任务号，审核和回传在后台排队 |
| 只记日志够不够？ | SQLite 事务把图片、项目和报警编号持久化。后续可去重、恢复、查询、补发。图片存 BLOB，列表页查询不取原图 |
| 后端怎样验收？ | 内部页面查看项目、报警、时间、状态、理由、原图及回调，并可上传联调样本 |
| 没有模型密钥怎么办？ | 正式 PPE 任务允许先收件等待，模拟用独立接口、令牌、数据库和回调接收器 |
| 同一张图片是否调用全部模型？ | 一个审核尝试使用当前选中的一个视觉模型。原候选是百炼 Qwen、MiMo、DeepSeek。负责人后来提供 DeepSeek 直连凭据，已验证并保留 deepseek-flash，目前正式外发暂停 |
| 为什么暂放 Mac？ | 先给 4S 一个能用的接口，尽快启动试点。图片和数据库放 Data 外置盘。正式主机和网络入口后续确定，平台接口保持 v1 |

现行流程为 **4S 推图 → SQLite 同时保存图片与任务 → 返回任务号 → 后台审核 → 保存结论与回调状态 → 回调 4S**。4S 也可以按任务号主动查询。任务号对应此服务的工作记录，报警编号对应原平台事件。

## 4　交付顺序与验收

| 阶段 | 负责人/配合方 | 交付与验收条件 | 本次状态 |
|---|---|---|---|
| 今天先收件 | 审核服务、4S 开发 | 拿到中文协议、令牌和测试图；提交一次得 202，重复提交得原任务号，重启后图仍可查 | Mac 端已验。待 4S 从自己的服务器实传 |
| 跑完整链路 | 审核服务、4S 开发 | 结果和原因可查；回调落库后确认；断网或中断能重试，相同回调可安全重复确认 | 本机已验。待提供正式回调地址、令牌及接收方重复确认行为 |
| 接公司可用模型 | 审核服务、账号负责人 | 图片真实到达选中端点，模型按约定输出；换型号能复验并回切 | DeepSeek 直连已验。百炼、MiMo 待提供相应权限后实测 |
| 本周单项目试点 | PM、现场同事、4S 开发、审核服务 | 后台可验收；平台测试同一报警是否正确展示和通知；建立人工答案并核对过滤建议 | 本机后台已验。现场样本、平台联调及业务验收待做 |
| 扩量及迁移 | IT、PM、审核服务、4S 开发 | 上新主机前完成恢复演练、网络互通、模型配额、实际峰值、磁盘容量、监控及回退验证 | 同一外置盘的隔离恢复演练见验证记录；目标主机待定 |

对话中的量级是单项目试点每天几百条，所有项目可能每天几万条，用于估算。单机当前每个环境各一条审核线程及一条回调线程。接单与审核能异步进行；审核吞吐取决于模型延迟、限额和重试。现有验证覆盖功能正确性，扩量能力需单独压测。

## 5　模型如何验收，哪些事还要拍板

准确性排第一，速度第二，成本第三。可先挑同一批有人工答案的告警，覆盖安全帽、反光衣、白天、夜间、遮挡、小目标、多人与原人员框错位。保留原图、ROI、原报警类型和人工理由，同一规则版本比较各模型。真实样本必须获准发送给相应模型服务。

至少分别统计**真实违规被误过滤的数量、正确筛出的误报数、无法确定的占比、技术失败率、接单到结果的中位数及第 95 百分位耗时**。成本按实际调用量、重试和账单核对。合成图和模拟结果不进入准确率统计。建议试点先让人工核对过滤建议，PM 签认判定边界与可接受风险后，再由平台决定是否自动隐藏。

4S 需确认项目开关、类型码、报警编号是否项目内唯一、图片来源与清晰度、ROI 坐标、回调鉴权与防重。PM 需决定服务断开或长时间没有结果时是否展示、是否通知、迟到结果如何处理。IT 需确认目标主机、数据卷、访问路径、每家云模型可接收的数据、配额与保留期限。以上决策不妨碍当前 Mac 先收图联调。
