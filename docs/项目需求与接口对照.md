# 4S 报警图片复核：项目需求与接口对照

现场摄像头已经报警，4S 按项目决定是否送审、何时展示和通知。复核服务接收这条报警的抓拍图，判断图片是否支持原报警，供 4S 追加标记。第一期处理未戴安全帽、未穿反光衣的单张图片，不读取摄像头实时流或视频。

## 需求与接口

| 需求 | 谁调用谁 | 接口如何满足需求 |
|---|---|---|
| 把报警与图片可靠地交给复核服务 | 4S → 复核服务，POST /api/v1/tasks | 提交项目编号、报警编号、报警类型和图片，可附审核区域 roi 和原算法人员框 person_boxes。图片和任务一起写入 Data 外置盘后返回 202 和 task_id。断线后原样重传，返回 200 和原任务号；同号改图或改字段返回 409。 |
| 随时知道某条报警处理到哪一步 | 4S → 复核服务，GET /api/v1/tasks/{task_id} | 用任务号查询处理状态 status、结论 verdict、理由 reason 和回调状态 callback_status。回调未配置或投递失败时也可查询。 |
| 有结果时自动回写到原报警 | 复核服务 → 4S，POST 至 4S 提供的 HTTPS 地址 | 审核完成或技术失败时发送结果。4S 用 task_id 关联原报警并去重，保存后返回 2xx。投递失败最多尝试 5 次。 |
| 确认发送服务器能访问服务 | 4S → 复核服务，GET /healthz | 免鉴权，正常返回 200 和 {"status":"ok"}。验证推图还要用测试项目走一次提交、查询和重传。 |

提交与查询使用复核服务发放的 Bearer 令牌。回调使用 4S 发放的独立令牌。

## 业务判定

省略 roi 时审核整图。指定区域时只判断区域内的人，且只看本条报警类型对应的违规。

| 情况 | 返回 | 说明 |
|---|---|---|
| 任一人明确存在对应违规 | valid，有效报警 | 由 4S 决定后续处理 |
| 有充分证据排除所有相关人员的对应违规 | false_alarm，误报 | 由 4S 决定是否过滤 |
| 无人、非现场、模糊遮挡导致证据不足，或属于一期未定义的危险区域、组合报警 | uncertain，无法确定 | 由 4S 决定后续处理 |
| 审核技术失败且重试耗尽 | status=failed，verdict=null | 可查错误原因 |

## 系统需求与当前状态

- **后台与存储**：任务、原图和结果保存在 Data 外置盘。内部后台可筛选任务、放大原图、查看理由、处理状态和回调状态。服务重启后从数据库恢复未完成工作。
- **更换模型与迁移**：模型端点、型号和密钥由服务端配置。更换模型时沿用 4S 的接口与任务号。Mac 是试运行主机，后续可停旧机、迁移数据库和配置，再在目标主机验收。
- **现在能用**：公网收图、存图和查询。安全帽及反光衣报警按统一流程发送给已启用的视觉模型。
- **真实审核**：启用模型后，真实安全帽、反光衣任务会发送至所选供应商。DeepSeek 接口模型链路已用合成图验证；现场图准确率仍需使用人工标注样本核对。
- **双方待完成**：4S 提供 HTTPS 回调地址和令牌，再从实际发送服务器验收推图和回调。公司内网地址分配后，用同一接口路径和测试图验证路由、端口与证书。
