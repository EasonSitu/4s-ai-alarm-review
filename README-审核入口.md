# 4S 告警复核服务 · Agent 审核入口

**交付基线为 2026 年 11 月 18 日（洛杉矶时间）。** 客户反馈现场 PPE 报警有误报。4S 希望多看一次报警图片，获取复核结论并自行决定是否过滤。现场摄像机已经报警，客户展示和通知由原 4S 平台负责。

多图协议以 [接口文档](docs/4S-API.md) 为准。一条报警提交 1–5 张图，共用任务号及回调；合并规则见 `app/store.py` 的 `aggregate`，真实审核提示词见 `app/review.py` 的 `review`，回归用例见 `tests/multi_image.py`。

本包可以独立审阅。先读下面的记录，再按问题追到源码和测试。Mac 是试点主机，当前模型可在本机后台查看和切换，启用后真实 PPE 报警会自动送至所选供应商审核。所有项目使用同一套接口和模型审核流程。部署位置、模型供应商及 4S 回调接收端分别配置。

## 给审核 Agent 的任务

请审阅这个版本能否进入**单项目、单机试点**。请独立判断迁移就绪程度和模型更换成本。先静态审阅源码；需要运行时，在自己的隔离副本里按验证记录复现。仓库不含图片，下载后按运行手册生成合成测试图。默认离线测试只访问回环地址。真实图片和生产凭据由试点负责人管理。

| 要回答的问题 | 核对位置 |
|---|---|
| 202 发出时，图片和任务是否已经一起提交？并发重传是否只产生一个任务？ | `app/main.py`、`app/store.py`、`tests/pilot.py` |
| 其他类型违规、图片模糊、模型超时、模拟结果是否返回约定的结论或空值？ | `app/contracts.py`、`app/review.py`、`app/store.py` |
| 第三方看到同一回调两次时会怎样？中断审核、回调和最后一次尝试分别如何恢复？ | `app/worker.py`、`app/store.py`、[协议](docs/4S-API.md) |
| 切换供应商后，发往哪个端点、用哪把密钥、历史记录如何解释？候选验证失败会发生什么？ | `app/config.py`、`app/model_profiles.py`、`scripts/manage.py`、`tests/profile_switch.py` |
| 主模型超时或失败后，备用模型是否安全接管？重启、配置更改和双方故障时如何处理？ | `app/model_catalog.py`、`app/worker.py`、`app/store.py`、`tests/model_fallback.py` |
| 换一台机器或一块盘，哪些文件必须跟着走？新旧主机能否同时投递？如何回退？ | `app/config.py`、`scripts/serve.py`、`tests/relocation.py`、迁移记录 |
| 真实工地图是否具备自动过滤的充分证据？评测样本、人员标注、延迟目标和规模验证还缺哪些？ | 背景与实施计划第 4、5 节，验证记录 |

请按**问题、影响、源码位置、复现方法、修复建议**给出发现，分别写明“阻塞试点”“扩量前处理”和“需要 PM 决定”的事项。请明确哪些结论来自运行证据，哪些仍属假设。审核报告可以直接交给项目负责人。

## 包内复验

在数据卷里的仓库目录，按运行手册建虚拟环境，运行 `.venv/bin/python scripts/generate_review_fixture.py` 生成合成图片后，再运行离线测试。仓库包含依赖范围及本机实际安装版本，供复现时核对。公开快照不包括历史图片、数据库和运行配置。
