# Windows Server 2016 部署

## 1. 进入服务器

Mac 上打开 Microsoft Windows App，选择 Devices → ＋ → Add PC，PC name 填同事提供的 IP。双击连接，使用同事提供的 Windows 账户。通过 RDP 的文件夹重定向或公司批准的文件通道，将部署 ZIP 复制到服务器。首次连接时与管理员核对服务器身份。

## 2. 安装

在服务器上确认独立本地数据盘的盘符及可用空间。以下以 D 盘为例。请创建新的 `D:\4s-review` 目录，将 ZIP 里的文件直接解压到其中，使 `D:\4s-review\windows\install.ps1` 存在。避开车载摄像头软件的目录。需要出站 HTTPS 访问 Python 软件源和模型供应商。

安装公司批准的 64 位 Python 3.12，选择为所有用户安装，并安装 Python Launcher。在服务器上以管理员身份打开 PowerShell，执行：

```powershell
cd D:\4s-review
py -3.12 --version
powershell.exe -NoProfile -ExecutionPolicy RemoteSigned -File .\windows\install.ps1
```

脚本检查 8765 和 8766 两个端口，冲突时退出。首次安装会创建两个使用 Local Service 账户的开机计划任务。仅在通过 ZIP 来源核验后，若远程来源标记阻止运行，可通过安装脚本属性页解除锁定。已有同名任务时脚本退出，避免覆盖现有安装。

## 3. 验收

在服务器自己的浏览器打开 `http://127.0.0.1:8765/admin`。后台账号为 `admin`，首次安装的随机密码保存在 `var\admin.secret`。在「模型设置」保存百炼北京的 API Key 和模型 `qwen3.8-flash`，再保存 DeepSeek 配置。将百炼设为主模型，DeepSeek 设为备用，15 秒切换，点击「验证并启用主备」。

在管理后台提交随包的 `examples\test-card.png`。它是合成测试卡，正常业务结论为“无法确定”，详情应记录实际模型。再在一次提交中选两张图，核对同一任务号下的两份明细和一条报警结论。

```powershell
Invoke-RestMethod http://127.0.0.1:8766/healthz
Get-ScheduledTask -TaskName '4S-Review-*' | Select TaskName,State
```

健康检查应返回 ok。已有的车载摄像头服务不需要重启。手动停止与启动本应用：

```powershell
# 维护时先禁用自动恢复，再停止进程
Disable-ScheduledTask -TaskName 4S-Review-Gateway
Disable-ScheduledTask -TaskName 4S-Review-API
Stop-ScheduledTask -TaskName 4S-Review-Gateway
Stop-ScheduledTask -TaskName 4S-Review-API

# 恢复服务
Enable-ScheduledTask -TaskName 4S-Review-API
Enable-ScheduledTask -TaskName 4S-Review-Gateway
Start-ScheduledTask -TaskName 4S-Review-API
Start-ScheduledTask -TaskName 4S-Review-Gateway
```

图片、数据库、配置和应用日志均在数据盘的 `var` 目录。日志为 `api.log`、`gateway.log`。全新安装会生成新的 4S Bearer 令牌，值位于 `var\config.json` 的 `live_token`，通过双方约定的私密渠道交付。模型 Key、4S 入站令牌、4S 回调令牌各自独立。

## 4. 让 4S 继续使用固定地址

本机 8765 提供管理后台。8766 是对接网关，默认开放任务、查询、健康和文档等路径。对外发布时，把固定 HTTPS 入口指向 `http://127.0.0.1:8766`，推送路径仍是 `POST /api/v1/tasks`。两端口默认只监听回环地址。

要沿用 Mac 的固定 ngrok 地址，在 Windows 配置同一 ngrok 账户及已分配的固定域名。验收后，先在 Mac 执行 `./4s public-stop`，再在 Windows 使用 ngrok agent 为同一域名连接上述网关，并按公司规范把隧道配置为开机运行。应从另一台电脑测试公网健康检查、授权提交及查询，同时确认后台访问状态与配置一致。若公司已有 HTTPS 网关，可由管理员在该网关配置域名、可信证书及转发规则。服务器的 RDP 地址只用于远程登录。

若需保留 Mac 的历史记录及原令牌，请约定切换时间。先停止两端服务，备份 Windows 试装数据；在专用加密传输通道中从已停止的 Mac 复制 `var/live` 整个目录及 `var/config.json` 到 Windows 的专用数据目录。保留 Windows 自身的后台密码及目录权限。复制前后校验文件哈希，启动 Windows 两个任务，再切换 HTTPS 入口。两台机器同时接收会把同一报警分散到两套数据库。需要退回时，先停新入口，核对并保全切换后新收的任务，再恢复 Mac。

## 5. 从公网登录任务后台

在 `var\public-admin-origin.txt` 中保存实际使用的 HTTPS 根地址，单行 UTF-8，无末尾斜杠。重启 `4S-Review-Gateway` 后访问该网址的 `/admin`，使用账号 `admin` 和 `var\admin.secret` 中的密码（至少 24 个字符）。本机反向代理须保留 Host，并传递实际的 HTTPS 协议。未登录应收到 HTTP 401，输入后台密码后即可查看任务及原图。4S 平台继续使用原 Bearer 令牌推图和查询。

删除该地址文件并重启网关即可关闭公网后台。入口关闭时，公网访问 `/admin` 返回 404。
